# In the Desktop app and VS Code: the plugin's mod

[← README](../README.md) · [status line](./editor-and-statusline.md) · [fix](./fix.md)

Claude Code's status line never runs in the Desktop app's Code tab or in the VS Code extension, so there the [status line](./editor-and-statusline.md#context-health-in-claude-codes-status-bar)'s cache clock never showed, and the limit ledger `context-doctor limits` reads stayed empty. The Claude Code plugin now carries a **mod**: code that Claude Code runs inside the session (in the terminal from 2.1.287, the Desktop app from 2.1.286, the VS Code extension from 2.1.299). It does five things, and a sixth once you apply it ([below](#the-desktop-apps-own-tools-behind-tool-search)).

**Getting it.** `context-doctor install` gives it to you: when every Claude Code on the machine is 2.1.286 or later (the Desktop app's bundled one counts), install enables the plugin in `~/.claude/settings.json` instead of wiring its own hooks, skill and MCP server ([what install writes](./install.md#claude-code-the-plugin-or-installs-own-wiring)). Claude Code fetches it in the background at its next start and loads it from the session after (`/reload-plugins` loads it at once). Or add it yourself: `/plugin marketplace add KushalP1/context-doctor`, then `/plugin install context-doctor@context-doctor`. `context-doctor doctor` says whether it is loaded and when the mod last measured:

```
✓ Claude Code route      the context-doctor plugin (enabled by install), downloaded (0.46.0): its MCP server, skills, hooks and mod
✓ Mod                    recording: last measured 4 min ago (~/.claude/.context-doctor-session-cost.jsonl); limits ledger written 4 min ago
```

**After each turn, it keeps the measurements.** Claude Code hands mods the rate-limit windows (Pro, Max and Ultra; Ultra has no 5-hour window) and its own cost of the session (`/cost`'s figure). The mod passes them to `context-doctor mod measure`, which:

- appends the 5-hour and weekly readings to `~/.claude/.context-doctor-limits.jsonl`, in the status line's format and with its rules (only changes, at most once a minute, never a lower figure of the same window from a parallel session), so `context-doctor limits` gets Claude readings from the Desktop app too;
- appends the MCP servers Claude Code handed the mod in this session (each one's type, tool count, and whether it went behind tool search already or by context-doctor's hand) to `~/.claude/.context-doctor-tools.jsonl`, one line per session and only when they changed, capped at 128 KB: what `fix` and `doctor` read to say whether `desktop-tools-defer` reaches the app's tools ([below](#the-desktop-apps-own-tools-behind-tool-search)). The mod notes them at `tool.describe` in memory and hands them over with the next turn's measure; it changes no tool for this;
- writes Claude Code's cost beside context-doctor's own price of the same session (the transcript and its subagents, priced as the every-prompt hook prices them) to `~/.claude/.context-doctor-session-cost.jsonl`, one line when either figure moves, capped at 512 KB. `context-doctor doctor` compares the two from Claude Code's own `cost-state` records in the transcripts, which need no mod (`Our price vs Claude Code's own: $338.28 against Claude Code's $339.47 (-0.4%) on 24 sessions…`; past a 2% gap, its biggest part, the rest in [spend](./spend.md)); where no transcript has one it says how close this ledger's pairs are: `Session price vs Claude Code: 11 of 12 sessions the mod measured in the last 30 days within 2% of Claude Code's own cost; the largest gap is +8% ($2.70 against $2.50, on claude-…)`. A model missing from context-doctor's price table, or contracted rates Claude Code gets from an MDM profile or server-managed settings (context-doctor reads `modelPricing` only from the managed settings files, [spend](./spend.md)), shows up as a gap; so does any error in context-doctor's estimate of a compaction's own request, which Claude Code's figure holds as billed and the transcript records no usage for ([spend](./spend.md)).

**A band above the prompt, off unless you turn it on.** In the Desktop app (Claude Code draws a mod's band in the terminal and the Desktop app; the VS Code extension has no such band, so there the mod keeps the measurements and opens the fix pane, and draws nothing above the prompt):

It is off by default: on a big session it came up after nearly every reply, and on a cold return the every-prompt hook already has Claude offer to compact in its answer. `CONTEXT_DOCTOR_MOD_BAND=cold` turns on the one case with a button; `CONTEXT_DOCTOR_MOD_BAND=always` shows everything below.

**On a cold return, a Compact first button (`CONTEXT_DOCTOR_MOD_BAND=cold`).** Back at a session of 150k tokens or more after its cache expired (past the cache's life by five minutes, as the every-prompt hook's cold-resume notice decides), the band says what the next message will cost and offers to compact first:

```
context-doctor: you were away 1h 20m, so the cache expired. Your next message re-sends this 520k-token chat at full price (~$5.20).
Compact first to shrink it: each message after that costs ~$0.02 instead of ~$0.26.
[ Compact first ]  [ Hide ]
```

`Hide` hides it for that idle period; the next one shows again. The cache's life is read from the transcript (the 5-minute or 1-hour entries the last reply wrote), because mods are not handed Claude Code's `prompt_cache`.

**`CONTEXT_DOCTOR_MOD_BAND=always`** shows the cold return and also the cache clock ("cache warm for 3 min, then your next message re-writes 520k tokens (~$5.20)"), the expired notice and the session price beside Claude Code's own figure ("session $42.10 (Claude Code: $41.90)"). These used to show by default (in the cache's last minutes, once it expired, and past $25, $100 and $500), but on a big session one of them was up after nearly every reply. In the terminal the status line shows them, so there the band shows only the cold return.

The button calls Claude Code's own compaction (`/compact`), between turns only: while a turn runs there is no button, and a press that meets one is a toast, not a compaction. A compaction Claude Code refuses for another reason (nothing to compact, a failed summary) is a toast with Claude Code's own reason. It is not offered past the point where Claude Code compacts by itself. Each press is counted in the cost ledger, so how often it is taken can be compared with the text offer's 1 in 33.

**`/context-doctor-fix`: the plan as buttons.** The command opens a pane with [`fix`](./fix.md)'s plan: each lever with its dollars over your last 30 days, its quality note and what it changes, and an **Apply** button; a lever `fix` applied has **Undo**. Each press runs the CLI's own `context-doctor fix --apply <id>` or `fix undo <id>`: the same lock, the same record in `~/.claude/.context-doctor-fixes.json`, the same files byte for byte as in a terminal. The subagents' model is marked **Apply (model change)** with a line saying its quality cost is not measured. A press while another `fix` holds the settings lock changes nothing and says so. Measuring takes a while on a long history, so a press does not re-measure: **Refresh** does. The command itself runs no Claude turn and costs no tokens.

**`/context-doctor-keep-warm 2h [$5]`: the cache kept warm while you step away.** Back after the cache expired, your next message writes the whole context again: on the author's 30 days 183 such returns cost $864 above cache-read price. Typed before you leave, this command keeps the cache alive: whenever the session has been idle for a tick under 55 minutes (4.5 on a 5-minute cache), it sends one ping through Claude Code's `$.model.fork`, which repeats the main conversation's last request with a one-line message after it. The context is read from the cache (which refreshes it), the fork's own message is never cached, and nothing is written to the transcript, so the conversation does not change. A ping costs one read of the context (~$0.10 for 520k tokens on Opus 5.5) plus a few output tokens; the band above the prompt shows how long it has left and what it has spent, with **Stop**. It stops for good when the hours (at most 8) or the dollar limit (default $2, at most $20) run out, when a ping finds the cache cold (it read nothing and wrote the context: the ping is counted, the next is not sent), when the cache lapsed before a ping could go out (Claude Code closed, or the machine asleep: a ping then would write the whole context), at `/clear` or a resume, at `/context-doctor-keep-warm off`, or with **Stop**. It never starts by itself or again after it stops: each absence takes the command. With no arguments it says what a ping would cost here and starts nothing. The yes, each ping and the stop go in the cost ledger. `context-doctor cache-misses` shows what it would have saved on your own history, by time away; on the author's, keeping warm for up to 2 hours nets $188 a month and past 8 hours a cold return costs less than the pings. The pings bill to your plan or API key: on a subscription they use your usage limit, as the re-writes they replace do. It needs a Claude Code whose mods API has `$.model.fork`: 2.1.321 and 2.1.325 do (read in their binaries and declarations), and the weekly canary arms it against its mock API and sees a ping arrive after the session's own messages. On an engine without it the first ping fails and keep-warm stops for good, saying so (a mod may not test for the call beforehand: `claude plugin validate` refuses that).

**`/context-doctor-usage`: the usage view the Desktop app dropped.** The app's update removed its usage and stats view ([#102264](https://github.com/anthropics/claude-code/issues/102264), [#102098](https://github.com/anthropics/claude-code/issues/102098), [#102130](https://github.com/anthropics/claude-code/issues/102130)) and its context ring ([#102094](https://github.com/anthropics/claude-code/issues/102094)), and 2.1.323 removed `subagentStatusLine` ([#109446](https://github.com/anthropics/claude-code/issues/109446)). The command opens a pane with them; for example:

```
         ≈ $5.04 of list-price use per 1% (±12%), this window; 1% moved from $25.00 to $5.04 7 days ago (5.0x less use per 1%)

[ Today $42.10 · 3.1M tokens ]  [ 7 days $841 · 90.0M tokens ]  [ 30 days $3,490 · 640.0M tokens ]

  Opus 5.5 · context 120k of 1.0M · $1.10 so far

```

- **The context ring** is Claude Code's own figure (what `/context` and the status line count: the last reply's input, cache reads and writes against the model's window), handed to the mod after each turn. The Desktop app and VS Code draw it as a ring, amber past 80% and red past 95%; the terminal as a bar.
- **The cache clock**, under the context: how long the prompt cache stays warm and what your next message costs if you send it now against after the cache expires (`Cache warm for 41 min. Your next message: ~$0.08 now, ~$3.30 after it expires.`), or, once it has, how long ago and what the next message re-writes (`Cache expired 12 min ago. Your next message re-sends the 412k-token chat at full price: ~$3.30.`). The clock starts at the transcript's last reply (or a `/context-doctor-keep-warm` ping, when later) and runs for the lifetime that reply wrote: an hour when its usage shows 1-hour cache writes (`cache_creation.ephemeral_1h_input_tokens`), else 5 minutes. "Now" is a cache read of the context, "after" a write of it at that lifetime's rate, at list price for the session's model, on Claude Code's own context figure. The pane's 30-second timer redraws it only when its words change. It is in this pane only, which you open: the band above the prompt stays off unless you turn it on.
- **The limit windows** are your plan's 5-hour and weekly windows, as Claude Code last reported them, with the pace and when the window runs out at that pace from the readings the mod keeps ([limits](./profiling.md#your-plans-limits-context-doctor-limits)). A plan with no 5-hour window (Ultra) shows the weekly one alone and says so. Under the weekly window, `limits`' per-reset figures ([limits](./profiling.md#your-plans-limits-context-doctor-limits)): the list-price dollars of use per 1% in this window (or, early in a window, in the last one with enough readings, said as such), with its error, and the latest move in that figure, dated. A window with too few readings for a figure gets no line. Off a subscription (an API key) there are no windows, and the pane says why.
- **Tokens and dollars by model** for today (since local midnight), the last 7 and the last 30 days, from the same requests [`spend`](./spend.md) reads, at list price; a button picks the period the by-model rows are for. Claude Code only: `spend` has Codex, Gemini CLI and Cursor.
- **Running subagents**, each with its type and task, its model, its context on its last request, and what it has cost so far (its transcript, priced as the session's price is). A finished one leaves the list.

Drawing the pane does no work: it shows what the mod holds. The figures come from `context-doctor mod usage`, which the mod runs when the pane opens, then on its 30-second timer only while the pane is open, and only when something is due: the 30-day history at most every 5 minutes (kept in `~/.cache/context-doctor/usage-pane.json`, so two sessions' panes share it), the subagents and the limit windows every 30 seconds while a subagent runs or after a turn. On the author's 22,000 requests over 30 days a refresh took 0.2-0.5 s with the history from that file and 0.8-1.3 s with the history measured again from `spend`'s transcript cache; a first run with no cache at all reads every transcript (2.7 s on an idle machine, 15 s on a busy one). A draw takes 0.2-0.4 ms (eight subagents, seven models). **Refresh** measures the history again at once. In the Desktop app's minimized pane (a widget) it is one line: `context 41% · today $42.10 · weekly 18% · 2 subagents`. Where nothing can draw a pane (`claude -p`, a headless host), the command answers with the same figures as text. Listing subagents needs Claude Code 2.1.325's `$.agent.list()`; on an older one the pane says it cannot list them and shows the rest.

Nothing happens without a press or a command: the mod never compacts, never applies a fix and never pings by itself. It writes no file of its own; the CLI it runs writes context-doctor's usual files. It needs `node` on the PATH Claude Code starts with, as the plugin's other hooks do; without it, the band falls back to Claude Code's own cost figure, at the thresholds `CONTEXT_DOCTOR_SESSION_PRICE` sets (none with `CONTEXT_DOCTOR_NO_SESSION_PRICE=1`), and the pane says why it has no plan.

## The Desktop app's own tools behind tool search

Off until you apply it. The Desktop app gives every session and subagent its own MCP tools (`Claude_Browser`, `ccd_session`, `visualize`, `terminal`, `ccd_turn`) with their definitions loaded upfront: about 12k tokens that each step re-reads, in sessions that mostly never call them ($88.63 of the author's 30 days for the first four). No setting reaches them. `context-doctor fix` prices it on your own starts, and `fix --apply desktop-tools-defer` (or **Apply** in `/context-doctor-fix`) writes the servers to keep back to `env.CONTEXT_DOCTOR_DEFER_MCP` in `~/.claude/settings.json` ([fix](./fix.md#the-desktop-apps-own-tools-desktop-tools-defer)).

The mod reads that variable at Claude Code's `tool.describe` event, which fires once per tool and session, and for a tool of a named server answers `isDeferred: true`: Claude then sees its name and loads it through tool search when it needs it, and again after a compaction, which puts loaded tools back behind tool search ([#111915](https://github.com/anthropics/claude-code/issues/111915); `fix` takes those loads off its figure). `ccd_turn` is never moved, whatever the variable says; a tool already behind tool search, a built-in, and every other server's tools come back as Claude Code gave them. The move waits for the next new conversation or `/clear`: the mod never sets `breakPromptCache`, so no running conversation's cache is written again. Unset (the default, and after `fix undo desktop-tools-defer`), with `CONTEXT_DOCTOR_NO_MOD=1`, or on a Claude Code before 2.1.326 (its `tool.describe` has no `mcpServer`, and an answer cannot place a tool), the mod changes nothing.

What is known without the app (Claude Code 2.1.330, read from its binary and run in the weekly canary):

- **In-process servers raise `tool.describe`.** Every tool Claude Code describes goes through the event, an MCP tool with `mcpServer.type` taken from its server's config, `sdk` for an in-process server like the app's. The one exception is a server that stands in for Claude Code's own built-in tools, which is described as a built-in (no `mcpServer`), and the mod leaves alone. The canary hosts two in-process servers the way an app does, each tool marked always-loaded as the app marks the ones it sends whole: the one named in `CONTEXT_DOCTOR_DEFER_MCP` goes behind tool search, the other goes whole.
- **The answer beats always-loaded.** A hook's `isDeferred` is read before the server's `alwaysLoad` and the app's list of tools never to defer.
- **Only where tool search is on.** With tool search off (`ENABLE_TOOL_SEARCH=false`, or a model or provider without it), Claude Code defers nothing that turn and the answer is ignored: the tools go whole as before, with no error (seen in a canary run with the variable off).
- **The first request of a session does not name it.** Claude Code lists the deferred tools before the hooks answer, so a moved tool is neither sent nor listed in a session's first request and is named from the second on. Tool search can still find it by keyword in the first.

**Seen on your own machine, before you apply it.** Applied or not, at each `tool.describe` the mod notes the tool's server, its type (`mcpServer.type`: `sdk` for an in-process server like the app's, `stdio`, `http` and so on for yours), and whether Claude Code already listed it behind tool search; after the turn, `mod measure` keeps one line per session in `~/.claude/.context-doctor-tools.jsonl` (changes only, capped at 128 KB; `CONTEXT_DOCTOR_NO_COST_LOG=1` turns it off with the cost ledger). Nothing is drawn and no tool moves for it. `fix` reads the newest Desktop session there: the app's servers that arrived whole with their server named are confirmed (`Claude_Browser (sdk, 12 tools) and ccd_session (sdk, 8 tools) arrive whole as in-process (sdk) servers … so this setting reaches them`), and one Claude Code already defers, or one the mod was not shown, is taken out of the lever with the reason, which withdraws it when none is left ([fix](./fix.md#the-desktop-apps-own-tools-desktop-tools-defer)). `doctor` says the same in a line:

```
✓ Desktop app tools      your Desktop session of 2026-11-24 handed context-doctor's mod Claude_Browser (sdk, 12 tools), sent whole; ccd_session (sdk, 8 tools), sent whole; ccd_turn (sdk, 1 tool), sent whole; context-doctor fix --apply desktop-tools-defer would move Claude_Browser and ccd_session (it reaches them)
```

After applying, the same line and `fix`'s applied row count the sessions in which the mod moved them (`moved behind tool search in 3 sessions since 2026-11-25`). The saving itself is then in `context-doctor overhead`: the servers should no longer be listed as sent whole in sessions started since.

## Turning it off

- **The mod alone:** `CONTEXT_DOCTOR_NO_MOD=1` in the environment Claude Code starts with (or in the `env` of `~/.claude/settings.json`). It then registers no command, draws nothing and runs nothing; the plugin's hooks, skills and MCP server stay.
- **Parts of what it keeps:** `CONTEXT_DOCTOR_NO_LIMITS_LOG=1` (the limit readings, as for the status line), `CONTEXT_DOCTOR_NO_COST_LOG=1` (the cost ledger and the tools ledger).
- **Every mod at once:** Claude Code's own switches: `"disableAllHooks": true` (which also stops settings hooks and the status line), or `--safe-mode` for one session. Disabling the context-doctor plugin in `/plugin` removes the mod with the rest of the plugin.

An older Claude Code (before 2.1.286) does not run mods; with one on the machine, `install` keeps its own wiring for every Claude Code there and says which one to update. The mod is named in `hooks/hooks.json`, beside only the model-switch hook, so a version that refused that file would lose that one hook and nothing else of the plugin.

## Checked every week on the newest Claude Code

A canary ([`scripts/canary.mjs`](../scripts/canary.mjs)) runs the plugin in a real Claude Code with no person and no network: `claude -p --plugin-dir` against a local mock of Anthropic's API, in a throwaway home with a made-up credential. It checks that the plugin loads, its hooks run (the every-prompt hook, the subagent and model-switch prices, the compaction instructions), that the mod's `session.measure` fires and writes the limits and cost ledgers above, that `/context-doctor-keep-warm 1h $1` arms and its ping reaches the mock through `$.model.fork` carrying the session's messages (a ping every 3 s there, `CONTEXT_DOCTOR_KEEP_WARM_PING_MS`, which only the canary sets), that `/context-doctor-usage` answers with the pane's figures (the mock's two windows, the session's own dollars), and that `claude plugin validate --profile directory --strict` passes. It runs weekly on npm's newest Claude Code and in the release checks, and goes red on each planted fault (a broken hooks file, a mod that throws on load, a renamed event, a hook that fails or prints invalid JSON). The band, the panes and their buttons are drawn by the app, which a headless session does not show; the mods test harness checks those (the usage pane on the desktop, the terminal and as a widget, from a fixture home). Details in [CONTRIBUTING](../CONTRIBUTING.md#checks-beyond-npm-test).
