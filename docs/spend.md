# Spend: `spend` and `budget`

[← README](../README.md)

Claude Code, Codex, Gemini CLI, Cursor, Copilot CLI, OpenCode and Cline each keep a record of what they sent, and none adds them up. `spend` reads them all from this machine and prints one bill: by tool, project, model and day, with what drives it, each request as billed at list rates (its tier, fast mode, US-only, web searches; below). `budget` sets a limit on it that the every-prompt hook applies while you work.

## One bill: `context-doctor spend`

```bash
context-doctor spend                 # the last 30 days (--days n), 8 rows per list (--limit n)
context-doctor spend --json          # everything, every day and session
context-doctor spend --share         # totals only, no paths or project names, to post (--copy)
context-doctor spend --by repo       # by git repository instead of project; --by branch: by repository and branch
context-doctor spend --export        # a file of totals for your team; spend merge <folder> adds a team's files up
```

### By repository and branch: `--by repo`, `--by branch`

Each request goes to the folder and branch it ran in, as each tool records them: Claude Code writes `cwd` and `gitBranch` on every row of a transcript, and a request takes the ones in effect when it was made (a session that switched branch, or moved into a worktree, is split there); Codex the `cwd` and `git.branch` of its `session_meta`; Copilot CLI `session.start`'s `context` (`cwd`, `gitRoot`, `branch`); OpenCode a message's `path`; Cursor and Cline the workspace folder. A folder's repository is the nearest folder above it holding `.git`, never the home folder itself; a git worktree (a `.git` file naming `<repo>/.git/worktrees/<name>`) counts as the repository it was cut from, so Claude Code's agent worktrees land in their repository; a folder gone from disk is walked up the same way; a folder in no repository is its own name. A tool that records no folder (Gemini CLI) keeps its project name; one that records no branch is "(no branch)". The total is unchanged; "By repository" (or "By branch") replaces "By project", and `--json` adds `repos` (and `branches`). The first run reads each Claude Code transcript once more for its folders and branches, then the cache keeps them.

### What it reads

| Tool | From | Counted |
|---|---|---|
| Claude Code | `~/.claude/projects/*/*.jsonl` (`CLAUDE_CONFIG_DIR` honoured) each session's `subagents/agent-*.jsonl`, and its workflow agents' `subagents/workflows/<run>/agent-*.jsonl` | every reply's `usage`, once: a reply written as several rows is one request (its output settled on the last row), and a forked session's copy of its parent is counted once. Workflow agents get their own line (`workflows $X (N runs)`); a session last written before the window still counts its subagents written in it |
| Codex | `~/.codex/sessions` and `~/.codex/archived_sessions` (`CODEX_HOME` honoured) | each `token_count` event whose running total moved (one that only refreshed the limits repeats the last request), a forked rollout's copy of its parent's events counted once; the model from `turn_context`, the project from the session's folder |
| Gemini CLI | `~/.gemini/tmp/<project>/chats/session-*.json[l]` | each `gemini` message's `tokens`, its last copy; a message later rewound was still billed, so it is counted; thoughts bill as output |
| Cursor | its `state.vscdb` (`cursorDiskKV`), needs SQLite (Node 22.13+ or the `sqlite3` command) | each agent reply's `tokenCount`, at the chat's model (`modelConfig.modelName`); the project from the workspace that lists the chat |
| Copilot CLI | `~/.copilot/session-state/<session>/events.jsonl` (and the flat `<session>.jsonl`; `COPILOT_HOME` honoured) | each `session.usage_record` event, one per model call: its input less both cache counts (Copilot's `inputTokens` holds them), its output (reasoning is inside it), the model less its `-1m` suffix; a call written twice once (its accounting id, else its API call id); a compaction (`session.compaction_complete`) as a call of its own unless a record names its request; the project from `session.start`'s `context.cwd`. Sessions from versions that write no usage records (only `session.shutdown` totals) are not read |
| OpenCode | `${XDG_DATA_HOME:-~/.local/share}/opencode` (`OPENCODE_DATA_DIR`, a comma list, instead): `storage/message/<session>/*.json`, and `opencode.db` (tables `message` and `session_message`), which needs SQLite as Cursor's does | each assistant message's `tokens` (input is uncached; reasoning, and any of `total` above the parts, as output), a completed compaction as a request of its own; a message in both the files and the database once; a forked session's copy of its parent's messages (`session_v2.fork_boundary`) not again; messages on the `claude-agent` provider are Claude Code's, counted from its transcript; the project from the message's `path.cwd`, else its session's `directory` |
| Cline | the editor extension's `globalStorage/saoudrizwan.claude-dev/tasks/<task>/ui_messages.json` (VS Code, VS Code Insiders, Cursor, Windsurf and VSCodium, each OS's folder checked), the older CLI's `~/.cline/data/tasks`, the CLI's `~/.cline/data/sessions/<id>/<id>.messages.json` (`CLINE_DATA_DIR`, a comma list, instead) | each complete `api_req_started` request (`tokensIn`, `tokensOut`, `cacheReads`, `cacheWrites`; one still `partial`, and the `deleted_api_reqs` and `subagent_usage` roll-ups, are not), its model `modelInfo.modelId`, else the task's model at that time (`task_metadata.json`), else counted unpriced; a CLI session's assistant `metrics`, its input less both cache counts; the project from the task's `cwdOnTaskInitialization` (`state/taskHistory.json`) where it is kept. Cline's own `cost` is not used: every tool is priced at list |

A tool with nothing on disk is left out. Prices are pricing.ts's list prices, cache writes by their TTL, the same code every other report prices with (`requestCost`: `spend`, the budget, the session price, `subagents`, `overhead`, `fix`'s replays). Claude Fable 5.2 and Mythos 5.2 are $8 / $40 per million, writes $10 (5 minutes) and $16 (1 hour), cache reads $0.20 (the page read 2026-11-10); 0.45 priced `claude-fable-5-2` by the Fable family's fallback row ($10 / $50, reads $1), an estimate five times too high on reads.

**At your organization's rates.** Where an administrator has set Claude Code's `modelPricing` in managed settings (contracted rates; [settings reference](https://code.claude.com/docs/en/settings-reference#modelpricing)), Claude Code reports `/cost`, the status line and `total_cost_usd` at those rates, and so does context-doctor: every Claude request is priced as Claude Code prices it, and the reports say "at your organization's rates" with a line naming the multiplier, the rows and the file. What it applies, read from the 2.1.321 binary and the reference:

| Field | Applied |
|---|---|
| `multiplier` (greater than 0, at most 10) | every Claude request's cost, a row's included: its tokens, fast mode, US-only, a long prompt's tier and its web searches |
| `overrides` (model id to `input`, `output`, `cacheRead`, `cacheWrite` per million, all four, each 0 to 10000) | the rates as written: `cacheWrite` for 5-minute and 1-hour writes alike, no fast-mode or US-only surcharge, no long-prompt tier; a web search keeps its $10 per 1,000. A key that names a Claude model (`claude-sonnet-4-6`) covers its dated, `[1m]`, Bedrock and Vertex spellings; any other key (a gateway alias) only that exact id, and wins over a model's row |

It is read only from the managed settings files Claude Code reads (`managed-settings.json` in `/Library/Application Support/ClaudeCode`, `/etc/claude-code` or `C:\Program Files\ClaudeCode`, then `managed-settings.d/*.json` in alphabetical order, merged key by key; `CLAUDE_CODE_MANAGED_SETTINGS_PATH` names one file instead), never from user, project or local settings, as Claude Code ignores it there. MDM profiles and server-managed settings are not read. Claude Code takes its managed settings from server-managed settings when there are any, else from an MDM profile, else from the files, and only from the first it finds (read from the 2.1.321 binary): on a machine with either of the others, Claude Code's own figures may use rates context-doctor cannot see, and may ignore the files' rates it applies. When Claude Code's copy of the server-managed settings (`remote-settings.json` in its folder) or a macOS managed-preferences profile (`com.anthropic.claudecode.plist`) is there, `spend` and `doctor` say so. Codex, Gemini CLI and Cursor stay at list prices. The budget's ledger and a session's price remember which rates and which price table priced them, and are priced again when either changes (a newer context-doctor that corrects a price re-prices the period, not only what comes after). `CONTEXT_DOCTOR_NO_MANAGED_SETTINGS=1` ignores managed settings altogether.

**Priced as billed, per request.** What a request recorded can bill it above its model's row, and each is applied where it is recorded (the providers' pages, read 2026-11-08):

| Modifier | Recorded as | Billed |
|---|---|---|
| Anthropic fast mode | `usage.speed: "fast"` | Fable 5.2 and Mythos 5.2 $16 / $80 (read 2026-11-10), Opus 5.5 $8 / $40, Opus 5 and Opus 4.8 $10 / $50 per million, over the whole context window; cache writes and reads keep their multipliers of that input |
| US-only inference | `usage.inference_geo: "us"` | 1.1x on every token category, for Claude 4.6 and later (earlier models reject it), on top of fast mode and Haiku 5.5's higher tier |
| Haiku 5.5's long prompts | a prompt over 100,000 tokens, cache reads and writes counted | the whole request at $0.50 / $2.50, cache reads $0.05 |
| Claude's web search | `usage.server_tool_use.web_search_requests` | $10 per 1,000 searches (web fetch is free; code execution bills container hours, which usage does not record per request: not counted) |
| OpenAI's long context | a prompt over 272k input tokens | 2x input, cached input and cache writes, 1.5x output, on the models the page gives a long-context price |
| Gemini Pro's long prompts | a prompt over 200k tokens | 3.1 Pro $4 / $18 / $0.40, 2.5 Pro $2.50 / $15 / $0.25 |

`spend` says what they added when anything did: "Of it, billed above list rates: fast mode +$X, US-only +$Y, web searches $Z (n), long-prompt tier +$W" under "Where it goes", the same line in `--share`, and `modifiers` (with `parts.webSearchUsd`) in `--json`. Not modelled: OpenAI's Fast mode (Codex records only its thread's `service_tier`, not each request's) and regional endpoints, the Batch API (no tool here uses it).

**Prices that end on a day.** A few rows hold until a known day: gpt-5.6-sol's promotion until November 30, 2026; Gemini 4 Argon's price until then (it doubles on December 1); Gemini 3.6 and 3.8 Flash until December 31, 2026 (doubling January 1, 2027); gemini-2.5-pro, routed to 3.8 Flash and billed at its rates from December 1. A request on or after that day is priced at what the page said would follow (the old price when it said nothing) and labelled an estimate, and every report that says so names which price ended and the price used instead: its model's row says "estimate: price ended 2026-12-01" (or "price changed" where the page gave the next price), and a note, `--share`, `budget` and `doctor` say, for example, "gpt-5.6-sol's price ended on 2026-12-01 and no later price is published: priced at the one that ended ($4 in / $20 out per M); an estimate; a newer context-doctor may know the price that followed", "gemini-4-argon's price changed on 2026-12-01: priced at the price the page said would follow ($4 in / $20 out per M)", or "gemini-2.5-pro's price ended on 2026-12-01: from then it is billed as gemini-3.8-flash, priced at gemini-3.8-flash's rates". (Before, they said only "price changed on 2026-12-01; a newer context-doctor knows the new one", which named neither price and promised a successor nobody had published.) `session` says it under Claude Code's own figure for a session that has such requests. A request made before the day keeps its price, whenever the report runs. A request recorded with no time of its own is priced as of when the report runs, as one priced past the day would be: it fits no day or period, so `spend`, the budget and `limits` leave it out, and the session price, `subagents`, `tasks` and the lens count it. A request on a model with no list price (a new or local model) is counted with its tokens and marked "not priced" (its tool's row, its model's row, a note; `--share` says it is left out), never shown as a free $0.00. A model the table knows only by its family (a release newer than the table, `claude-opus-9`) is priced at that family's row and said to be an estimate: its model's row, a note with the dollars, `--share`'s "Of it, $x is on models priced as their family", and `budget`. Replies Claude Code writes itself on `<synthetic>` (an error, an interruption) never reached the API: they are not counted at all. Cursor's own names for Claude (`claude-4.6-opus-high-thinking`) are priced as the Claude version they stand for (`claude-opus-4-6`), shown as Cursor wrote them.

**A compaction's own request, estimated.** Compacting sends the whole conversation once more and gets the summary back; Claude Code bills that request and counts it in its own cost, but its transcript records no usage for it: only the `compact_boundary` row (`preTokens`, the context it read) and the summary (a user row). `spend`, the budget and a session's price add each one as an estimate, at the model of the reply before it (with that reply's fast mode and US-only, the organization's rates, the day's price): the context at the cache-read rate, however long the session sat idle before it; its output, the summary's length in tokens (20,000 when no summary row follows). Not counted: the request's own instruction and any thinking it did. `spend` says how many and what they came to ("Of it, 3 Claude Code compactions' own requests $3.34, an estimate"; `compactions` in `--json`); `savings` leaves them out, as it bills only what the rows record. A budget ledger or session price kept by an older version is read again once to add them. **Read, not written again: what Claude Code's own figure shows.** Until 2026-11-15 a compaction past the cache's lifetime was priced as the context written again. Claude Code's `cost-state` rows (below) say otherwise: on the author's machine 33 compactions fall between two of a session's records, and in the 24 brackets that hold nothing else no row records, Claude Code's figure moved by about the cache-read price, never by a write (a 221k-token Fable 5.1 compaction after 5.4 hours idle: $0.44 above our rows; read, $0.29; written again, $4.66; an 874k-token one, $0.76 against $0.60 read and $17.87 written). The other 9 brackets hold more than either estimate. With the write, the session with the most compactions was 10.7% over Claude Code's figure; read, it is 1.2% under.

**Calls inside a request that its usage totals leave out.** One API request can hold several model calls, each itemized in `usage.iterations` with its own tokens and, where it differs, its own `model`, and the top-level usage counts only some of them. The advisor tool: the top-level usage is the sum of the executor's iterations (`message`), and each `advisor_message` is billed on top at the advisor model's rates (Anthropic, "Advisor tool", usage and billing). A server-side fallback: the top-level usage is the attempt that answered, and each earlier attempt (the declined model's, its own `model`) is billed on top ("`usage.iterations` is the per-attempt source of truth"). Which iterations are extra is checked on the tokens, never assumed from the types: the non-advisor iterations must add up to the top-level prompt, or the last of them must equal it; a shape that is neither has only its advisor iterations added, so nothing is counted twice. Each extra iteration is priced by `requestCost` at its own model, cache writes by their lifetime, with the request's US-only and fast mode. `spend` shows each as an item on its own model (not a request of its own: not in the counts) and says what they came to ("Of it, 1 attempt a fallback model replaced $5.56 (claude-fable-5), beyond their requests' usage totals"; `iterations` in `--json`); the budget, a session's price, `session`, `subagents` and `tasks` add them to the request's price. `savings` and the replays in `fix` price the request's own usage, which is what their levers change. On the author's machine (read-only, 2026-11-15): no advisor call yet (sessions declare the tool, none consulted it), and 10 replies (34 rows) a server-side fallback answered, 2026-06-10 to 2026-08-25: Fable 5 declined each after reading 83k-641k tokens, and the 8 of those attempts in `spend --days 200`, in no total before, come to $41.97.

**Claude Code's own figure beside ours.** Every Claude Code transcript carries `cost-state` rows: Claude Code's running total for the session (`totalCostUSD`, what `/cost` shows) and, per model, the tokens and dollars it counted. It writes one at points through a session and restores it on resume, so the last one is the session's total so far; it counts every request its process made for the session, subagents included, and also what no transcript row records: a compaction's own request (estimated here, above), its own small requests on a Haiku (titles and the like, and its web searches), a request a model declined that it sent again on another (`model_refusal_fallback`), and from 2.1.325 other mods' own model calls. `spend` compares, for every session whose record and requests fall wholly in the window, Claude Code's last figure with ours over the same span (from the session's start to the last reply before that record, subagents included), and takes the gap apart per model with Claude Code's own token counts: models it counted that no row has (its side requests, with how many web searches; a declined request, with how many refusals the transcript recorded), its tokens beyond or short of ours on the models both count, priced at ours (requests no row records the usage of; our compaction estimates), and what is left, its prices against ours on its own tokens. Writes Claude Code did not split by lifetime (before about 2.1.317, and the early part of a session resumed across it) are priced at what ours cost per token on that model in that session. `session` shows it for one session, `doctor` checks it over the last 30 days ("Our price vs Claude Code's own"), and `--json` has every session (`claudeCode`). It replaces the mod's measurement as the check; the mod's ledger is used by `doctor` only when no transcript has a record.

On the author's machine (read-only, 2026-11-15, a throwaway cache), with compactions priced as read: the 24 sessions wholly in the last 14 days, Claude Code **$339.47**, ours **$326.48** (-3.8%), 13 of the 18 over $0.50 within 2% (the session that was +10.7% with compactions written again is -1.2%). **Subagent progress summaries, estimated beside the total.** While a background subagent runs, Claude Code asks a model every 30 seconds for the 3-5 word line on its task row, and makes that request with `skipTranscript`: Claude Code bills it, but no transcript has a row for it ([#86879](https://github.com/anthropics/claude-code/issues/86879) measured 22.7% of one subagent-heavy session's requests). The Desktop app's Code tab runs Claude Code through the SDK (not interactive) and its bundle never sets the option, so its sessions have none. **Cursor is an estimate.** Its history keeps a prompt's size and the reply's, with no cache split, so every input token is priced uncached: an upper bound. Replies on Auto (`"default"`) have no list price (Cursor bills Auto from your plan): they are counted, with their tokens, and not priced. The report says both.

**Copilot CLI: list price, and what Copilot counted.** Copilot bills its plan in AI credits (one is $0.01) and, before those, premium requests; each usage record carries both (`copilotUsage.totalNanoAiu`, in billionths of a credit, and `cost`, the request's multiplier: 1, or more for a premium model). `spend` prices the record's tokens at the model's list price, as it does every tool's, and says beside it what Copilot counted: "53 AI credits" on Copilot's row, and a note "Copilot counted 53 AI credits ($0.53 at $0.01) and 2 premium requests" (`credits` and `premium` on the tool in `--json`). A model with no list price (`auto`) is counted, not priced. A call on your own key (BYOK) is priced the same. GitHub documents none of this record; the shape is the one GitHub's own agent-radar collector and the other readers parse (checked 2026-11-15), and `src/test/spend-copilot.test.ts` holds a fixture of it.

**Against `savings`.** `savings` bills a narrower slice of the same Claude Code requests: the main conversation's input (cache writes and reads, not output), in sessions with 10+ requests. `spend` counts every request in the window, output and subagents too. On the requests both count (compactions' own requests are `spend`'s alone) the dollars are the same, to the cent; `src/test/spend.test.ts` checks it, and on the author's history the 36 sessions `savings` counts come to $2,332.37 in both. `spend`'s Claude Code total equals what `limits` reads for the same window.

**On a subscription** the same tokens come out of your plan's limits instead of a bill: the dollars say which tool and project use the most, not what you paid. Past a limit, with extra usage on, they do become a bill: Claude Code keeps working on usage credits. When the limits ledger shows that happened in the period (a window that read 100% while requests kept going, or the API's own `overage-in-use` header recorded by the proxy; see [limits](./profiling.md#your-plans-limits-context-doctor-limits)), `spend` splits Claude Code's dollars under its tool line: "Past your plan's limit since Tue, Nov 17 at 14:05: $41.20 of Claude Code's $812, 37 requests, paid from usage credits, at API list prices (an estimate). The other $771 was inside the plan." Requests counted only from a 100% reading say "likely ... (inferred from 100% readings)". `--json` has it as `credits` (`usd`, `requests`, `claudeUsd`, `fromHeaders`, `inferred`, `since`), absent when nothing went past a limit. Whether credits bill at exactly API list prices is not verified, so the figure is an estimate.

## A team's spend: `spend --export` and `spend merge`

A manager wants one view across people and tools without a vendor dashboard, and nothing here sends anything anywhere. So each person writes a file, puts it where the team already shares files (a drive folder, a repository), and anyone adds the folder up:

```bash
context-doctor spend --export                      # context-doctor-spend-<you>-<day>.json here; or --export <file>, --export - for stdout
context-doctor spend --export --as "Priya" --by branch --anonymize --days 30
context-doctor spend merge ~/Drive/ai-spend        # --json for everything, --limit n rows per list
```

**What an export holds: totals only.** One row per local day, tool, model and repository (and branch with `--by branch`): requests, tokens (uncached input, cache reads, cache writes, output), dollars at list price, requests on a model with no list price, and Copilot CLI's AI credits and premium requests. No prompt or reply text, no path, no project, session or file name: a repository is its folder's base name (`shop`, see [By repository and branch](#by-repository-and-branch---by-repo---by-branch)); a request whose tool records no folder is `(no folder)` (Gemini CLI keeps its project's name, a folder's base name or Gemini's hash). `--anonymize` replaces each repository and branch name with a hash of it (`repo-1f3a…`, the same name giving the same hash on every machine, so a team's files still line up; a short name can be guessed from its hash by trying names, so it hides names from a casual reader, not from someone who knows your repositories). The developer is a label you choose with `--as`, by default your OS user name. The file is plain JSON: read it before you share it.

**What `merge` prints.** The total, the month of the last day so far and a month-end forecast at the pace of the last 14 days (fewer when the files hold fewer; labelled an estimate), then by developer, by repository (and branch when the files carry branches), by tool and by model. Developers are listed in alphabetical order, not ranked: the per-repository and per-tool views are the ones meant for decisions. A developer's files that cover the same day (an export run twice) count that day once, from the newest file; a developer whose latest file ends before the others' last day is named, as the days after count nothing for them. Files in the folder that are not exports are skipped and named; subfolders are not read. `src/test/spend-team.test.ts` checks that an export holds no prompt text or path and that merging three exports equals their sum, per developer, repository and tool.

## A budget the hook applies: `context-doctor budget`

Every report is after the fact. A budget is said while you work: before each prompt, the every-prompt hook adds up what today (or this week) has cost across Claude Code, Codex and Gemini CLI, priced as `spend` prices it, and tells you once when it reaches 50%, 80% and 100%.

```bash
context-doctor budget 50/day            # or 200/week (from Monday); dollars at list prices
context-doctor budget 50/day --block    # over it, hold prompts instead of only saying so
context-doctor budget                   # where today (or this week) stands; --json
context-doctor budget off               # remove it
```

What you see, once per threshold per period:

```
context-doctor: $41.20 spent today (Claude Code $40.10, Codex $1.10): 82% of your $50/day budget.
```

**Past the plan's limit.** With extra usage on, Claude Code keeps working when a 5-hour or weekly limit runs out, and those requests are paid from usage credits, real money. They are already in the budget's dollars (every request is priced the same way); the warning at a threshold and `budget` say how much of it ran past the limit, when the limits ledger says a limit ran out or the API's replies said credits were in use:

```
context-doctor: $41.20 spent today: 82% of your $50/day budget. $12.40 of this was paid from usage credits, past your plan's limit (37 requests, at API list prices, an estimate).
```

Found only from 100% readings (the Desktop app, where the proxy does not run), it says "was most likely paid" and that it was inferred, as `limits` does. `budget --json` adds `credits` (`usd`, `requests`, `fromHeaders`, `inferred`; `null` when nothing ran past a limit). How a budget is set does not change, and the status line's `$12/$50 today` stays as it is.

Requests on a model with no list price cannot count toward a dollar budget: the hook says so once a period (`3 requests are on gpt-7, with no list price, so the budget does not count them.`), and `budget` on every run.

**Holding prompts.** With `--block`, over the budget every prompt is held, with the reason and how to lift it: `context-doctor budget off`, or a higher budget (`context-doctor budget 75/day --block`; without `--block` a new budget only warns); it lifts by itself at midnight (Monday for a week). Each host's documented way:

| Host | Hook | Says so | Holds the prompt |
|---|---|---|---|
| Claude Code | `UserPromptSubmit` | `systemMessage` | `decision: "block"` with the reason: the prompt is erased and the reason shown |
| Codex | `UserPromptSubmit` (trust the hook once: `/hooks`) | `systemMessage` | `decision: "block"` with the reason |
| Gemini CLI | `BeforeAgent` | `systemMessage` | `decision: "deny"` with the reason |
| Cursor | `postToolUse` only | no | no: its prompt hook cannot add a line, and its spend is not counted (its history is a database too slow to read on every prompt; `spend` shows it) |

The status line (`install --statusline`) shows `$12/$50 today` in place of the session's cost while a budget is set, and `doctor` reports the budget and whether a hook is there to apply it.

**Where it lives.** `~/.claude/.context-doctor-budget.json` holds the budget, `~/.claude/.context-doctor-budget-state.json` the period's ledger (in `CLAUDE_CONFIG_DIR` when set); the thresholds said this period are marker files in `.context-doctor-budget-said.d` beside them, so of several prompts at once exactly one says each; `budget off` and `uninstall` remove all three. On a machine without `~/.claude` (Codex or Gemini CLI alone) they, and the hook's other files, go to `~/.local/state/context-doctor` (`$XDG_STATE_HOME`, `%LOCALAPPDATA%` on Windows) instead: a `~/.claude` made for them read as Claude Code to `install`. A budget is in whole cents (`50.555/day` is $50.56, and says so).

**Kept fast.** The hook runs on every prompt, so the period's spend is a ledger: per transcript, its size, time and inode, and the period's requests in it (a short key and the dollars). The first prompt of a period reads each transcript written in it once, through the transcript cache; after that a prompt reads only what was appended to the ones that changed, and a fork's copy of its parent's replies counts once, by key. Codex's rollouts are found in the period's own date folders on every prompt, and by a full walk of its folders every five minutes (a resumed session is appended in its older folder, so its spend can be up to five minutes late): with 3,000 rollouts the walk took 16 ms a prompt, now 0.6 ms. The ledger's total equals `spend`'s full read of the same period (`src/test/budget.test.ts`, and on the author's history after 45 appended replies: $63.9947 both). With no budget set the hook pays one failed file read.

**On the author's machine** (read-only: the real transcripts, a throwaway Claude config folder and cache, today's 86 MB transcript copied and grown one reply per prompt): the budget check adds **~5 ms** to a hook run (median of 25 interleaved runs, 115 ms without a budget, 120 ms with one), 2.9 ms measured in-process (max 14 ms); a prompt with nothing changed, 2.6 ms. The first prompt of a day with nothing cached at all takes ~0.35 s more, once. The ledger: 39 files, 32 KB.

## A session's own price, while it runs

The budget counts a day; one session can cost hundreds of dollars on its own without anyone noticing that each message now re-reads half a million tokens. So the same every-prompt hook (Claude Code, Codex, Gemini CLI; budget or not) adds up what this session has cost, its subagents and workflow agents included (they bill to it), and says so once when it passes **$25, $100 and $500**:

```
context-doctor: this session has cost $112 so far ($30.00 of it subagents); each message now re-reads ~470k tokens (~$0.118). /compact, or a handoff to a new session, cuts that.
```

The per-message price is the main conversation's context at its last request, at its model's cache-read rate as the next request bills it (fast mode and US-only as the last one recorded, the tier of that context's length). After an idle long enough for the prompt cache to expire, it says what this message pays to write the context again instead (`the cache expired while it was idle, so this message re-writes its ~470k tokens (~$9.40), and each one after re-reads them`), and the hook's own cold-resume line is then left out, so the re-write is said once. Right after a compaction, or when Claude Code is about to compact this very prompt, it says the cost alone. Gemini CLI is told `/compress`.

- **Once per threshold per session.** A session first seen past $100 hears $100, not $25 as well. Each threshold is claimed by creating a file that must not exist yet, so of several hooks running at once for one session exactly one says it.
- **To you, not the model.** It is a `systemMessage`, like the budget's lines: compacting or moving to a new session is your decision about your money, and only you can run `/compact`. The cold-resume offer, while it lived only in the model's reply, was acted on 1 time in 33; and a note in the model's context is paid for on every later request. (Past its token threshold the hook's note to the model already asks it to offer a compaction.)
- **Thresholds**: `CONTEXT_DOCTOR_SESSION_PRICE=50,200` (dollars; set it in the hook's environment, e.g. Claude Code's `env` setting). **Off**: `CONTEXT_DOCTOR_NO_SESSION_PRICE=1`. `doctor` shows which are in force.
- **The status line's cost** is Claude Code's own `cost.total_cost_usd`, at its prices; the hook's figure is `spend`'s for the session's transcripts, at list prices (equal by test, `src/test/sessionprice.test.ts`). They can differ: Claude Code prices with a managed price table when one is set (context-doctor reads the one in managed settings files, above, but not one from MDM or server-managed settings), and after a resume its running total may start again. A session resumed or forked into a new one starts with a copy of the old one's rows, which keep the old session's id: the hook counts only the rows of its own session, so the copy is the old session's cost, not this one's.
- **Codex's spawned agents** bill to the thread that spawned them and are in its figure, as its subagents: each one's rollout names the thread in its first `session_meta` (`parent_thread_id`, also under `source.subagent.thread_spawn`; Codex Desktop 0.146), so the hook reads only that first line of the rollouts written since the thread began (in its day folders and the archive), each once: what it named is kept with the session's state, and a later prompt reads only rollouts new since (2,000 candidates: 0.6-1.1 s a prompt before, 17-28 ms after, in a throwaway home), and a forked agent's copy of the thread's history counts once. `spend` counts those requests in the thread's session too (equal by test, `src/test/codex-subagents.test.ts`); a thread you forked yourself (`forked_from_id` only) stays a session of its own. On the author's machine, the one thread that spawned agents (three, July 31) is $0.73 with them, $0.33 without.
- **What the figure holds** is said briefly beside it: the subagents' and workflow agents' part, a part on a model the price table knows only by its family (an estimate), and requests on a model with no list price, which are not counted. When the line has told you to `/compact`, the model is not also asked to offer it.
- **Kept fast.** The cost is the budget ledger's per-transcript entry, with the period starting at the session's first request: a prompt reads only what was appended to the session's transcript and its subagents'. The entries go beside the hook's per-session state, and only once 512 KB has been read since they were last written, or a threshold is said: a session below $25 with a short transcript writes nothing. Codex's and Gemini CLI's files are read through the transcript cache. Once $500 is said, the check is one `stat()`.

**On the author's machine** (read-only, 2026-11-04, a throwaway cache): of the 45 sessions active in the last 30 days, **15 passed $25** in the window and went on to spend **$3,369** after it (median $54 a session; the largest, $2,031), **5 passed $100** ($2,639 after; median $93) and **2 passed $500** ($1,688 after: $1,556 and $133). The median session passing $25 re-read ~303k tokens a message (~$0.07), $100 ~706k (~$0.14), $500 ~765k (~$0.19): most of the money after a threshold is the count of messages, subagents and cache writes, not one message's read. Latency on a copy of the largest session (97 MB, 274 subagent transcripts), each prompt after a 150 KB append: the check adds **~13 ms** to a hook run (median of 9 interleaved runs, 170 ms without it, 183 ms with it), 7.3 ms in-process (max 10 ms). The first prompt on a long session the hook has not seen reads it whole, once: 1.65 s for that one.
