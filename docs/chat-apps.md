# Chat apps and agents: what runs by itself, and what only nudges

[← README](../README.md)

context-doctor ships an MCP server, so the AI itself can profile and slim context on demand. The honest question is **on which surfaces it acts by itself, and on which it only nudges**. MCP gives a server no way to see the conversation or intercept a turn; only a hook or a place in the data path can do that. The README's [platform table](../README.md#where-it-works) is the summary; this page has the detail behind each row.

## Which surfaces act by itself

**Claude Code: yes.** The hook runs on every prompt and the status line on every refresh. Past ~80k tokens the model receives hygiene guidance naming the largest waste, and compaction is offered. Measured: 115 automatic checks, 48 warnings, across 32 sessions on one machine.

**Cursor: yes, since 0.26.** `install` adds a native `postToolUse` hook to `~/.cursor/hooks.json`; Cursor passes it the agent transcript, and its `additional_context` reaches the model. In a heavy chat the agent gets hygiene guidance and the largest recoverable waste, once per 40% of growth. Cursor's transcript records tool calls but not their output, and keeps turns Cursor has since summarized, so the note gives the chat's accumulated size, with no window share or price. Corrected in 0.26: Cursor also runs Claude Code's hook, but as `beforeSubmitPrompt`, whose output can only allow or block the prompt, so from 0.15 to 0.25 the guidance never reached Cursor's model.

**Codex (ChatGPT.app's Codex tab, the Codex IDE extension, the `codex` CLI): yes, since 0.16.** `install` writes the hook to `~/.codex/hooks.json`, the MCP server to `~/.codex/config.toml`, and the skill to `~/.codex/skills/`. Codex uses Claude Code's hook contract almost verbatim and passes its own rollout transcript, which carries the API's real usage figures, so the guidance comes from measured tokens. One extra step, Codex's rule not ours: a new hook runs only after you trust it once (type `/hooks` in Codex). The MCP tools are marked read-only, so Codex runs them without an approval prompt, `codex exec` included. `session` and `session --list` read Codex rollouts too.

**API traffic through the proxy: yes.** Every request passes through it with no model involved; with `--autopilot`, stale tool output is cleared whenever the cache is cold ([the proxy](./proxy.md)).

**Claude Desktop: a nudge.** The server sends the standing rules as its MCP `instructions` on every connect. Whether classic Chat puts them in front of the model is **unverified**: until 0.36 this page said the app bundle proved it, citing Desktop's `LocalMcpServerManager`, but that class serves Cowork (agent mode; its MCP clients are named `local-agent-mode-<server>`). Classic Chat pipes MCP through the renderer to the claude.ai client, which reads the instructions from the server; whether it adds them to the model's context we could not trace (checked 2026-10-26 in the app bundle and the claude.ai client code). Desktop also gets one-click prompts in the **+** menu (`context_checkup`, `handoff`, `ask_file`), attachable handoffs, and since 0.17 a `profile_context` the model can actually afford to call from chat. Until 0.17 the tool wanted the whole conversation as its argument, so calling it from chat meant re-typing 50k tokens; nobody did, and Desktop's log showed zero calls in a month. Now the model passes a ~120-token **sketch** (turn count, the large or repeated blocks) and gets a sized estimate, findings and the fix to apply. Still a nudge, not a hook: Desktop chat has no hook API and no transcript on disk.

**What no chat app allows: editing the history.** Desktop, claude.ai and ChatGPT keep the chat on their side. A model that summarizes a big paste stops quoting it, but the paste is still re-read on every turn. The tokens come back only in a **new chat**, so the findings say that, and the cut is a [handoff](./handoff.md): a ≤400-token brief the model writes, saved locally and attached to (or pasted into) the next chat.

**The ChatGPT chat UI: no.** No MCP, no hooks, no data path in the chat product itself. Use Codex, or a developer-mode connector at a URL you host (below).

So "every chat inherently better" is true for Claude Code, Cursor, Codex and the proxy; for Claude Desktop it is "the rules are sent to every chat, the checkup is one cheap tool call away, and a handoff is one click"; and not a claim we make for the ChatGPT chat UI.

## Claude Desktop, step by step

1. Run `context-doctor install` and restart Claude Desktop, or open the `.mcpb` from the [latest release](https://github.com/KushalP1/context-doctor/releases/latest) (Settings > Extensions): same server, no npm, it runs on Desktop's own Node.
2. From then on, the MCP server hands Desktop the [six standing rules](../README.md#where-it-works) on every connect (whether classic Chat shows them to Claude is unverified, see above): call `profile_context` once at ~30 turns and before answering any question about tokens, cost, speed or limits; when a chat grows long, offer a handoff once; summarize big pastes instead of re-quoting them; refer to earlier content by name and never inline base64; use `pack_context` for big local files; write the summary `optimize_context` asks for.
3. That call is cheap on purpose. Claude cannot export a Desktop chat, so it passes a **sketch**: how many turns, which blocks are large, repeated, stale or images, with one size hint each (~120 tokens). The server sizes it (usually within ±20%, measured; see [token counts](./tokenizer.md)), prices the per-turn re-read (on a subscription that is what spends your usage limit), and returns ranked findings with the action for each: "summarize *the nginx config* into the points still needed", "refer to *test output* by name", "offer a handoff once". The reply ends with an instruction to apply the top one, not just suggest it, and says what that does and does not do in a chat app: working from a summary stops the chat growing, while the tokens already in it (the "recoverable ~97k") come back only in a new chat, through a handoff.
4. One click instead of asking: the `context_checkup` prompt in the **+** menu sends that request for you.
5. When the chat is long: the `handoff` prompt (**+** menu) has Claude write a ≤400-token brief plus the blocks that must stay exact, saves it (Desktop asks first where it can show a form), and tells you the per-turn saving. Open a new chat and attach `handoff://latest` from the **+** menu. Details: [handoff](./handoff.md).
6. For a big local file: the `ask_file` prompt takes a path and a question and has Claude call `pack_context` instead of reading the file whole.
7. Say *"optimize it"* on an exported conversation and Claude applies the safe fixes; if you agree to pruning old history, **Claude itself writes the replacement summary** (that's the no-API-key summarization).

What this does not do: read the chat behind Claude's back or trim it for you. Desktop chat has no hook API and no transcript on disk (checked in the app bundle, v2.2553). The model does the trimming, when the rules and the checkup tell it to.

## ChatGPT

ChatGPT's MCP support differs fundamentally from Claude Desktop's: **it never launches a local process**. Its custom connectors (developer mode) have OpenAI's servers connect to a **URL**, so the MCP server must be reachable from the internet.

1. **Normal ChatGPT (no developer mode): no MCP at all.** context-doctor still helps via the CLI: export the conversation and run `npx context-doctor analyze chat.json --model gpt-5` / `optimize` (or `session conversations.json` on a full data export). The standing rules go in your preferences (next section).
2. **ChatGPT developer mode**: run the HTTP transport somewhere reachable — `context-doctor-mcp --http --port 8808 --allowed-hosts <your-host>` on a small host (bind `--host 0.0.0.0` there), or expose your machine temporarily with a tunnel (`ngrok http 8808`) and start the server with `--allowed-hosts <the tunnel's host name>`. Since 0.37 the server answers only to the host names it knows (localhost, 127.0.0.1, [::1], a named `--host`, and `--allowed-hosts` or `CONTEXT_DOCTOR_ALLOWED_HOSTS`); any other Host gets a 403 that names the flag, and the startup line lists the accepted names. Then Settings → Connectors → Advanced → Developer mode → add a connector with the URL `https://<your-host>/mcp`.
3. Once connected, GPT gets the same five tools, each marked read-only (they read their input and return text; `save_handoff` is marked as a write only with `--store-handoffs`), with the same trigger guidance: ask *"what's eating my context?"* → it calls `profile_context`; *"optimize it"* works the same, including GPT writing the pruning summary itself; *"hand this off"* → it writes the brief and calls `save_handoff`, which over HTTP stores nothing and has GPT print the handoff for you to paste into a new chat (`--store-handoffs` keeps them on the machine running the server; see [handoff](./handoff.md)).
4. Files you upload in ChatGPT reach `pack_context` directly: over HTTP the tool declares `openai/fileParams`, so ChatGPT passes an uploaded file as `{download_url, file_id, mime_type, file_name}` and the server downloads it (https only, redirects never to http, no private or loopback addresses, 5 MB per file, 20 s) and packs only the chunks your question needs. The server reads no files from its own disk over HTTP.
5. Results are compact for ChatGPT: it shows the model both a tool's text and its `structuredContent`, and keeps `_meta` for widgets. So when a call carries ChatGPT's `openai/session` or `openai/subject` metadata (its anonymized conversation and user ids), `profile_context` and `pack_context`'s outline return one or two lines of text plus the findings or sections as `structuredContent`, and the full report in `_meta`: 54% fewer characters on the sample conversation's profile, 51% on an outline of this repository's docs. Every other client gets the full text as before (`CONTEXT_DOCTOR_RESULTS=compact` or `full` overrides).
6. **ChatGPT desktop, Work (Local)** runs on Codex and reads `~/.codex/config.toml`, which `context-doctor install` already writes: there the server runs locally over stdio, with the handoff resources and file paths like any local client.

Security note for step 2: the HTTP endpoint is unauthenticated — put it behind your tunnel's auth or a reverse proxy if it stays up long-term. Over HTTP it reads no local files, writes nothing to the ledger, stores no handoffs unless you pass `--store-handoffs`, and exposes no handoff resources. It checks Host and Origin on every request, so a web page cannot reach it through DNS rebinding or a cross-site post (`--allowed-origins` lets a web client of your own through; ChatGPT's origins are allowed by default), caps request bodies at 10 MB, downloads uploads only over https from public addresses, and reads documents without loading anything they link to, within a time budget per call. ChatGPT's guide says the first 512 characters of a server's instructions should stand alone, so the first four rules end exactly at character 512.

## claude.ai on the web and the phone apps

Where there is no hook and no MCP at all (claude.ai on the web, the Claude and ChatGPT phone apps, plain ChatGPT), the app's per-account preferences are read on every turn, which is the closest those surfaces have to a hook. `context-doctor instructions --copy` puts the ~190-token rules on your clipboard and tells you where to paste them: claude.ai Settings > General > personal preferences (applies everywhere you are signed in, phone included); ChatGPT Settings > Personalization > Custom instructions, "What traits should ChatGPT have?". On claude.ai you can instead upload `skills/context-doctor/SKILL.md` under Settings → Capabilities → Skills. Either way web and mobile conversations gain the same standing habits: summarize, don't re-quote, and once a chat is heavy, offer a handoff (a 400-token brief to start a new chat with, since the history itself cannot be trimmed).

## MCP tools

| Tool | What it does |
|---|---|
| `profile_context` | Token breakdown by category, largest messages, findings with estimated savings. Takes either `conversation` (full JSON or text) or `sketch` (turns + large/repeated blocks, for chat apps) |
| `optimize_context` | Rewrites the conversation: dedupe, trim stale tool results, strip base64, optional history pruning. A result over 100k characters is not echoed back; you get the summary and the CLI command instead |
| `pack_context` | Only the chunks of large local files or folders (absolute paths, or passed `text`) that a question needs, within `max_tokens`; outline without a query; `ids` to fetch more. Reads no files over HTTP |
| `context_best_practices` | Curated checklist, optionally specialized for Anthropic / OpenAI |
| `save_handoff` | Stores a handoff brief (≤400 tokens) and the blocks that must stay exact, masks secret-looking strings, and returns the per-turn saving and how to continue in a new chat. Over HTTP it stores nothing unless `--store-handoffs` ([handoff](./handoff.md)) |

Prompts, in clients that show them (Claude Desktop's **+** menu, Claude Code's slash menu, VS Code, Cursor, Gemini CLI): `context_checkup`, `handoff` (write, save and continue in a new chat) and `ask_file` (a path and a question, answered through `pack_context`). Resources, on the local server: `handoff://latest` and `handoff://<id>`, attachable in Claude Desktop, Cursor, VS Code (Add Context) and Claude Code (`@`).
