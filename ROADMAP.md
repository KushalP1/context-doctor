# context-doctor roadmap

**Goal:** no one pays for tokens that do nothing. context-doctor measures where context goes on your own machine, in every app you use, and removes the waste at the moments it pays: before it enters the context (pack, overhead), while it sits there (hook, autopilot, compact-window) and after the fact (profile, optimize, savings).

Guiding principles, in priority order: **dead simple for everyone** · **works always, everywhere** · **provably saves tokens, dollars, latency** · **never needs an API key for core function**. Every claim in the README is a measurement on real sessions; an idea that does not survive measurement is closed here with the numbers (see [Closed by measurement](#closed-by-measurement)).

Feedback and votes: [open an issue](https://github.com/KushalP1/context-doctor/issues).

## Research 2026-10-26: what users need

What people complain about in 2026, from GitHub issues and Hacker News, and what the platforms changed underneath them. Ranked by how many people it touches.

- **Limits drain with no audit.** Claude Code issues with "usage limit" in the title: 822; the top ones are [#16157](https://github.com/anthropics/claude-code/issues/16157) (726 👍) and [#38335](https://github.com/anthropics/claude-code/issues/38335). Codex: [#28879](https://github.com/openai/codex/issues/28879), the per-token cost of the same work jumped 10-20x. HN: [47586176](https://news.ycombinator.com/item?id=47586176), [47923357](https://news.ycombinator.com/item?id=47923357). Codex has no usage meter at all ([#23794](https://github.com/openai/codex/issues/23794)), and people switch tools when they hit the limit ([#21073](https://github.com/openai/codex/issues/21073)).
- **Silent cache regressions after an upgrade.** Claude Code [#46829](https://github.com/anthropics/claude-code/issues/46829) (the cache TTL dropped from 1 h to 5 min, 341 👍), [#46917](https://github.com/anthropics/claude-code/issues/46917), [#45381](https://github.com/anthropics/claude-code/issues/45381); Codex [#35416](https://github.com/openai/codex/issues/35416), [#24704](https://github.com/openai/codex/issues/24704).
- **Compaction loses work, and a cold `/compact` burns a 5-hour limit.** [#17428](https://github.com/anthropics/claude-code/issues/17428), [#27242](https://github.com/anthropics/claude-code/issues/27242).
- **Fixed overhead and MCP bloat.** "33k tokens before reading the prompt" ([HN 48883275](https://news.ycombinator.com/item?id=48883275)).
- **Subagent fan-out with no cost confirmation.** Claude Code [#66023](https://github.com/anthropics/claude-code/issues/66023), Codex [#31814](https://github.com/openai/codex/issues/31814).

Limits moved to tokens. Codex plans are metered in credits per token since 2 April 2026, cached input at 10% ([rate card](https://help.openai.com/en/articles/20001106-codex-rate-card)); GitHub Copilot bills per-token AI Credits since 1 June ([GitHub](https://docs.github.com/en/copilot/reference/copilot-billing/request-based-billing-legacy/what-changed-with-billing)); Claude does not publish how its 5-hour and weekly limits weight cached tokens. On the OpenAI API, GPT-5.6 and later set the cache lifetime with `prompt_cache_options.ttl` (`"30m"` default, `"12h"`, both minimums) and bill writes at 1.25x (30 min) or 2.5x (12 h) input; GPT-5.5 and older keep `prompt_cache_retention`, which defaults to `"24h"` for organizations without Zero Data Retention ([prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), read 2026-10-26).

Others in the space: [ccusage](https://www.npmjs.com/package/ccusage) (827k npm downloads a month), [CodeBurn](https://github.com/getagentseal/codeburn), [Claude-Code-Usage-Monitor](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor), [rtk](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman), [context-mode](https://github.com/mksglu/claude-context-mode), [Headroom](https://github.com/chopratejas/headroom) (a local proxy on port 8787, autopilot's port), [repomix](https://github.com/yamadashy/repomix). They count tokens or compress them; none shows the limit in the user's own unit (% of the 5-hour window) with verified savings and reversible, cache-safe clearing. That is the gap.

## Research 2026-10-27: what changed since 2026-10-20

Claude Code 2.1.309-2.1.311, Codex 0.164, Cursor's October changelog, the MCP 2026-07-28 spec and SDKs, Antigravity's docs, and the issues filed since 2026-10-19.

- **The cache TTL still regresses, and loops resonate with it.** Interactive CLI sessions write 5-minute entries since 2.1.301 ([#103673](https://github.com/anthropics/claude-code/issues/103673)); a self-rescheduling agent woke every 61-62 minutes, just past a 60-minute cache, and paid $248 of $285 in cache writes over 89 wake-ups ([#104736](https://github.com/anthropics/claude-code/issues/104736)). The 2.1.308 binary clamps `ScheduleWakeup` to [60, 3600] s and tells a 1-hour session that "every allowed delay" stays cached, though a 3600 s delay counted from the end of a turn lands after the TTL counted from its last request. On the author's last 30 days (86 transcripts, 9,637 main-chain requests over 20k): 240 requests re-wrote a cold cache (129M tokens); 8 of them came less than 25% past the TTL (5.1M tokens).
- **Claude Code now says why the cache missed, and when it goes cold.** The status line input's `prompt_cache` (2.1.251+) carries `warm`, `ttl`, `expires_at`, `recache_tokens_if_cold`, `misses`, `miss_recache_tokens`, `last_miss_at` and `last_miss_cause.causes` (`tools_changed`, `system_prompt_changed`, `ttl_expired_5m`, `likely_server_side`; 2.1.260+), and Claude Code re-runs the status line when `expires_at` passes ([status line docs](https://code.claude.com/docs/en/statusline), read 2026-10-27). context-doctor's status line read none of it; `cache-misses` explains 381 of its 390 misses as "nothing visible". 2.1.311 also fixed `/usage` never showing large cache misses.
- **Limits.** "Opus usage limits draining ~5x faster" ([#105125](https://github.com/anthropics/claude-code/issues/105125)), usage rising while idle, measured with packet counters ([#104614](https://github.com/anthropics/claude-code/issues/104614)), a self-imposed cap ([#105111](https://github.com/anthropics/claude-code/issues/105111)). `limits` (R2) already records the readings; a cap is a later candidate.
- **Codex.** 0.164 adds observation-only `PreModelRequest`/`PostModelRequest` hooks with token usage, stops double-counting retained reasoning on Responses Lite ([#55991](https://github.com/openai/codex/pull/55991)), and lets hosts control `prompt_cache_key` ([#55587](https://github.com/openai/codex/pull/55587)). A first request after 11 h 44 min hit 0% of a "persistent" cache ([#56050](https://github.com/openai/codex/issues/56050)), within R1's 24-hour assumption only as a ceiling.
- **MCP.** The 2026-07-28 spec (stateless, `server/discover`, `ttlMs`/`cacheScope` on list results) lives in the TypeScript SDK's v2 packages (`@modelcontextprotocol/server` 2.4.0); the v1 line ends at 1.32.2 with fixes only (same-origin redirects, `maxToolInputElements`, `tools/call` without arguments). The spec adds: servers SHOULD return `tools/list` in a deterministic order "to improve LLM prompt cache hit rates" ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)).
- **Antigravity** (2.12.0 on the author's machine) documents MCP in `~/.gemini/config/mcp_config.json` (`mcpServers`, `command`/`args`/`env`, `disabled`, `enabledTools`/`disabledTools`; [MCP](https://www.antigravity.google/docs/mcp)) and global skills in `~/.gemini/config/skills/<name>/` for the app and IDE, `~/.gemini/antigravity-cli/skills/` for the CLI ([skills](https://www.antigravity.google/docs/skills)). Hooks (`~/.gemini/config/hooks.json`, `injectSteps`) hand over a `transcriptPath` whose format is still undocumented, and none exists on the author's machine (13 `brain/` folders, empty `logs/`).
- **Competitors.** rtk (84.7k stars, v1.1.0 on 2026-10-25) wraps shell commands to compress output, which we closed by measurement (2026-10-13); CodeBurn (11.6k) added one-click updates; Claude-Code-Usage-Monitor has not changed since July. None reads Claude Code's own miss diagnosis.

## Research 2026-10-28: from reports to fixes

The product has ~40 commands, 2 GitHub stars and ~4k npm downloads a month (ccusage: ~800k). The last three rounds were mostly measurements. This round asks where the biggest avoidable tokens go for typical users in October 2026, which of them a local tool can remove with no loss of quality, and what makes someone try it.

**The evidence that decides it: the measurements are not acted on, not even by the author.** On the author's last 30 days (`savings`, read-only, 34 sessions with 10+ requests, $2,789 of input at list price), an earlier auto-compact window would have saved $1,423 (51%), compacting at cold returns $640, and autopilot $278 in a terminal; the author has `autoCompactWindow` unset, and the cold-resume `/compact` offer was followed 1 time in 33. A user has to read several reports and type the right command for each. The biggest lever left is turning the findings into applied, reversible settings.

**MCP tool-definition bloat (candidate a): mostly solved by the hosts themselves.** Checked per host (docs, changelogs, source, and the installed binaries read-only):

But a gateway would now help only Gemini CLI, Antigravity and older-model VS Code sessions, and on the author's real configs (read-only) it saves nothing: Claude Code and Claude Desktop list only context-doctor, Cursor three servers (deferred by Cursor), Antigravity's `mcp_config.json` is empty, no Gemini CLI. **Not built**; `overhead --mcp` already sizes each server, and Claude Code's one remaining case (tool search switched off in settings) becomes a fix in B1.

**A lever in the subscription apps nobody uses (candidate c): the prompt cache's lifetime.** Claude Code 2.1.243 added `promptCacheTtl` and `subagentPromptCacheTtl` (`"5m"`/`"1h"`; env `CLAUDE_CODE_PROMPT_CACHE_TTL`, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`; [env vars](https://code.claude.com/docs/en/env-vars), [CHANGELOG 2.1.243](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). Unset, the main conversation gets 1 hour "on a Claude subscription within its usage limits, 5 minutes on an API key, Bedrock, Vertex or Foundry" (the setting's own description in the 2.1.309 binary), and subagents 5 minutes. The default has regressed before (5-minute writes in interactive sessions since 2.1.301, [#103673](https://github.com/anthropics/claude-code/issues/103673); R3 measured the 1-hour share at 76% → 37% → 70% across versions). A 1-hour write costs 2x input instead of 1.25x but survives a 5-60 minute pause. Replayed on the author's last 30 days (read-only prototype, each request priced at its model's rates, a cold-to-warm flip only where the gap falls inside the new lifetime and no compaction or model switch came between): main conversation as billed $2,820 (70% of writes at 1 hour); every request at 1 hour $2,624 (**−$196, 7%**); every request at 5 minutes, Claude Code's default on an API key, $3,392, so for an API-key user with the author's pace the 1-hour setting saves **$768 (23%)**. Subagents (441 transcripts, all 5-minute) would cost $238 more at 1 hour: the default is right there. The content sent is identical either way: no quality question at all.

**Adoption (candidate d).** The first run already measures (`npx context-doctor` = `savings`), but ends in reading, not in a change. Anthropic now runs an official plugin directory (`anthropics/claude-plugins-official`, submissions at claude.ai/directory/manage after `claude plugin validate`, [submit](https://claude.com/docs/plugins/submit)); the listing is the owner's step, the plugin passing validation is ours.

## Closed by measurement

Ideas that were built or specified, measured on real sessions, and dropped because the numbers did not justify them. Newest first.

### 2026-10-18: server-side tool-result clearing (`clear_tool_uses_20250919`)

The idea: let the API clear old tool results itself (context editing, beta `context-management-2025-06-27`), in the proxy and `withContextDoctor`, which keeps thinking signatures valid where autopilot's rewrite can be refused. `scripts/replay-server-clearing.mjs` replays the author's last 30 days (37 Claude Code sessions with 10+ requests, $3,345 billed) three ways, priced as the prompt cache bills: as sent; with autopilot; and with the API's rule simulated (past `trigger`, every request clears all but the last `keep` re-runnable results, so each newly cleared result rewrites the cache from that point on). Autopilot: 11.0% saved, no session more expensive. The API's defaults (100k, keep 3): 9.4% saved, 12 sessions more expensive (worst 47% more). With `clear_at_least` 20k: 9.4%, 7 more expensive (worst 48%). 200k, keep 5, at least 50k: 2.4%, 14 more expensive (worst $27). The rule ignores whether the cache is warm, which is the one thing that makes clearing safe. Not shipped.

### 2026-10-18: capping oversized MCP results in Cursor (`updated_mcp_tool_output`)

The idea: Cursor's postToolUse hook may replace an MCP tool's output, so oversized MCP results could be cut before they enter the context. Cursor's transcripts never record tool output, so the measurement used the author's Claude Code history, which runs the same kinds of MCP servers: 9,064 MCP results in the last 30 days (1,306 transcripts), median ~600 tokens, p99 ~4.3k, largest ~20k; 29 exceeded 10k tokens, and capping them at 10k would have removed ~137k tokens, 1.6% of MCP result tokens. Most of the volume is browser screenshots, which a text cap cannot shrink. Not shipped: a lossy rewrite of content the model asked for, for a saving that small.

### 2026-10-13: distilling noisy tool output in a PostToolUse hook

The idea: Claude Code 2.1.295 lets a PostToolUse hook replace a tool's output (`updatedToolOutput`), so a hook could strip the noise from large results before they enter the context: ANSI codes, carriage-return and progress-bar lines, repeated identical lines, blank-line runs, runs of passing tests, install chatter. Measured on the author's last 30 days (455 transcripts including subagents, 50,803 tool results, ~61M tokens, ~$5.1k at list price counting each result's cache write and every later re-read until compaction), those rules remove 130k tokens (0.2%), about $19. On results over 4k tokens, where the hook would act, they remove 34k tokens, about $3. The large results are content the model asked for and may edit from: `sed -n` and `cat -n` file reads (8.0M of the 13.3M tokens in Bash results over 4k), grep, `git diff` and `git show`. Rules that keep exact text must leave those alone, and the rest is screenshots. Test, build and install output is already trimmed at the command: 96% of 1,226 such commands went through `tail`, `head`, `grep` or a quiet flag, median 95 tokens, none over 4k. The hook would add a ~80 ms process start to ~1,700 tool calls a day to save about $3 a month.

### 2026-10-12: telling the model a re-read file is unchanged

The idea: before a `Read`, say "you already have this, unchanged since turn N". Across 998 reads in 78 sessions (30 days), one returned content identical to an earlier read of the same range in the same session, about $0.10 at list price. Repeated reads of one file were different ranges of a large file. Nothing to save.

### 2026-10-08: a large-paste notice in the hook

The idea: when a prompt itself carries a big paste, tell the model to work from extracted points. Across 2,233 prompts in 75 local Claude Code sessions, 51 carried 5k+ tokens and 10 carried 10k+ (largest 14k), in sessions that run to hundreds of thousands of tokens. A notice cannot take a paste back out of history, so the most it could save is a few percent of a few sessions, paid for with a line of context on every large prompt. `pack` is the better answer: the document never needs pasting.

### 0.18.0: Cursor `beforeReadFile` trimming

The item assumed the hook could rewrite file content. In Cursor 3.18.25 the `beforeReadFile` response validator accepts only `permission: allow|deny` and `user_message`; the local agent runtime reads the same two fields and nothing else. The only inherent action is to deny a read and tell the agent why. Then the measurement, on 735 `Read` calls across 13 real Cursor agent transcripts: Cursor's agent already ranges 82% of its reads (`offset`/`limit`); whole-file reads have a median size of 4.6 KB and a p90 of 26 KB; 6 of 735 reads exceeded ~10k tokens and none exceeded 200 KB. A deny guard would fire on under 1% of reads, save 10-25k tokens each time, and break a workflow whenever its threshold was wrong. Not shipped. Cursor's transcript also never contains tool results, which is why the hook there reports estimated sizes only.

### 0.13.8: `trim-tool-calls` stays opt-in

The question was whether trimming a completed tool call can confuse a live agent.
Across 42 sessions: 73 large writes, 18 later edited, and 16 of those edits had no
read in between — the model built `old_string` from its own `Write` input, at a
median distance of 43 messages (p90: 181). So yes, in about 22% of cases, and far
outside any recent-message window. Default stays off. What shipped instead: the
offline optimizer, which can see the rest of the conversation, now keeps exactly
those writes and trims the 63% that are never touched again.

### 0.13.0: calibrating the heuristic from transcripts

**"Calibrate the heuristic from ground truth"** assumed transcripts record what is
sent. They do not. A turn with 5,595 characters of visible content is billed
14,002 tokens, which would imply 0.4 characters per token — denser than any real
tokenizer. Claude Code injects per-turn content (reminders, skill and file text)
that never reaches the transcript, so transcript-derived calibration would fit
the estimator to noise. Calibration needs a real tokenizer, not this data.

## Shipped in 0.12.0 — durability and the biggest real waste

| Item | Why |
|---|---|
| **Installs survive a Node upgrade** | `install` wrote `process.execPath`, which on Homebrew/nvm/asdf is version-pinned: the next Node upgrade deleted that path and every config broke silently. Configs now use `node`/`npx` from PATH, `doctor` flags any surviving pinned command, and re-running `install` repairs stale entries instead of skipping them |
| **Hooks never point into the npx cache** | `npx context-doctor install` wrote a hook path inside npm's garbage-collected `_npx` directory; when npm cleared it the every-prompt hook failed silently forever. The hook now prefers a checkout or a global binary, and says how to get the fast path |
| **Large tool calls are found and fixable** | In file-heavy agent sessions the biggest items in context are tool CALLS, not results — a Write or a heredoc carries the whole file inline. New `large_tool_call` finding plus an opt-in `trim-tool-calls` strategy: on a real 278k-token session, 278k → 102k where the default set reached 248k |
| **No more phantom base64** | A run of one repeated character or a long hex digest matched the base64 charset, so `strip-base64` replaced real content with a placeholder. Detection now also requires the character distribution of encoded binary |
| **Huge transcripts actually parse** | Sessions past V8's ~512MB string limit threw inside the hook, where the error was swallowed — the biggest sessions got no warning at all. Transcripts are now streamed line by line |
| **Broken input says so** | A truncated or non-conversation JSON file produced a confident report about one giant "user message"; the report now leads with what went wrong |
| **Readable findings** | Repeated findings of one kind collapse into a single line instead of burying the other kinds |
| **Node 20+** | Node 18 went EOL in April 2025 and its CI jobs hung indefinitely, so `engines: >=18` was a promise we could not keep. CI now covers exactly what package.json claims, on three OSes |
